# 导入文本格式 v1（family-health-import/1）

> 外部 AI 整理报告文本 → App 粘贴导入 / HTTP API 提交 的统一契约。
> 与 `02-数据库与同步.md` 对应：本格式是**写入载荷**，字段命名与数据库一致，导出物可再导入。

---

## 1. 基本原则

1. **整体原子**：一次提交 = 一个完整业务单元（一次复查 / 一批测量 / 一组用药变更），任一字段非法则**整体拒绝**，绝不写半截。
2. **幂等**：`import_id` 由提交方生成（UUID）。服务端对同一 `import_id` 的重复提交返回首次的处理结果，不重复入库。
3. **未知字段忽略**：v1 内允许新增可选字段，旧客户端/服务端必须忽略不认识的字段（仅前向兼容；破坏性变更升 version=2）。
4. **原文存档**：指标名、单位、参考区间一律保留医院原文，归一只发生在重点清单的别名配置里，不在导入时改写。
5. **人工验证前置**：提交方（外部 AI + 人工核对）对内容准确性负责；服务端只做模式与合法性校验，不做医学合理性判断。

## 2. 信封（Envelope）

```json
{
  "format": "family-health-import",
  "version": 1,
  "import_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "dry_run": false,
  "profile_ref": { "name": "爷爷" },
  "payload": { }
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| format | string | 是 | 固定 `"family-health-import"` |
| version | int | 是 | 一期固定 `1` |
| import_id | string(uuid) | 是 | 幂等键 |
| dry_run | bool | 否，默认 false | true = 只校验返回结果，不写库 |
| profile_ref | object | 是 | 二选一：`{"id": "<profile_uuid>"}` 或 `{"name": "<档案名>"}`；按名字在本家庭内解析，不唯一或不存在 → 拒绝 |
| payload | object | 是 | 见第 3 节，三种载荷任选其一 |

HTTP 通道：`POST /api/v1/import`，Header 携带 `Authorization: Bearer <api_token>` + `Idempotency-Key: <import_id>`（与体内 import_id 必须一致，不一致拒绝）。App 粘贴通道复用同一解析与校验管线，区别仅在解析后增加人工预览确认步骤。

## 3. 载荷 A：checkup_event（复查事件，含报告与指标）

```json
{
  "type": "checkup_event",
  "event": {
    "checkup_date": "2026-08-15",
    "hospital": "市人民医院",
    "department": "肾内科",
    "note": "医生嘱三个月后复查，ACR 较上次升高，继续观察",
    "next_checkup_date": "2026-11-15",
    "medication_changes_note": "停用缬沙坦，改服氯沙坦 50mg 每日一次",
    "reports": [ ]
  }
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| checkup_date | date `YYYY-MM-DD` | 是 | 不允许未来日期（容忍 +1 天时区误差） |
| hospital / department | string ≤50 | 否 | 自由文本 |
| note | string ≤2000 | 否 | |
| next_checkup_date | date | 否 | 须晚于 checkup_date；写入后刷新复查提醒 |
| medication_changes_note | string ≤2000 | 否 | 仅展示性备注；**用药条目的实际变更走载荷 C**，二者可同时提交 |
| reports | array | 是 | 1~30 份 |

### 3.1 report（报告）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| title | string ≤100 | 是 | "尿常规"、"肾脏 B 超" |
| report_date | date | 否 | 缺省 = 事件 checkup_date |
| conclusion_text | string ≤5000 | 否 | 描述性结论（B 超所见/提示等） |
| attachment_ids | string[] uuid | 否 | 引用**已上传**的附件 id（附件经独立上传通道先行上传，见 02 文档 4.4） |
| indicators | array | 否 | 0~200 项；纯描述性报告（B 超）可为空 |

### 3.2 indicator（指标项）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| item_name | string ≤100 | 是 | 医院原文名称 |
| value | number 或 string | 是 | number=定量；string=定性（"阴性","弱阳性","+"）≤50 字 |
| unit | string ≤30 | 否 | 原文单位（"μmol/L"、"%"） |
| reference_range | string ≤50 | 否 | 原文照录（"41~81"、"<30"） |

规则：
- 数组顺序即报告原始顺序，服务端按序存 `sort_order`。
- value 为 string 且可无损解析为数字时按定量处理（防止 AI 输出类型抖动）；无法解析则按定性存档。
- 指标示例（尿常规同时存在两类）：
```json
{ "item_name": "尿蛋白", "value": "阴性" },
{ "item_name": "尿微量白蛋白", "value": 156.3, "unit": "mg/L", "reference_range": "<30" },
{ "item_name": "尿肌酐", "value": 8.82, "unit": "mmol/L" },
{ "item_name": "尿微量白蛋白/肌酐比值(ACR)", "value": 201.5, "unit": "mg/g", "reference_range": "<30" }
```

## 4. 载荷 B：measurements（批量测量）

```json
{
  "type": "measurements",
  "items": [
    { "type": "bp", "measured_at": "2026-08-15T07:30:00+08:00",
      "systolic": 138, "diastolic": 86, "heart_rate_bpm": 72 },
    { "type": "glucose", "measured_at": "2026-08-15T07:35:00+08:00",
      "glucose_mmol": 6.1, "glucose_context": "fasting" }
  ]
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| items | array | 是 | 1~500 条 |
| type | enum | 是 | `bp` / `glucose` |
| measured_at | ISO8601 带偏移 | 是 | 不允许未来时间 |
| systolic / diastolic | int 40~300 | bp 必填 | 高压>低压 时警告（见 6.2 非阻断警告） |
| heart_rate_bpm | int 20~250 | bp 时可选 | 脉搏，随血压附属 |
| glucose_mmol | number 0.5~40 | glucose 必填 | |
| glucose_context | enum | glucose 必填 | `fasting`/`before_meal`/`after_meal_2h`/`bedtime`/`random` |
| note | string ≤500 | 否 | |

> 数值合法性区间只用于拦截明显的手误/格式错乱（如收缩压 1380），**不代表医学正常范围**，越界即拒绝并提示核对。

## 5. 载荷 C：medication_changes（用药变更）

一次提交描述一组同节点变更（对应时间轴上的一个变化节点）：

```json
{
  "type": "medication_changes",
  "effective_date": "2026-08-15",
  "linked_event_id": null,
  "reason_note": "复查后医生调整",
  "stop": [ { "match": { "name": "缬沙坦" }, "end_date": "2026-08-15" } ],
  "start": [
    { "category": "long_term", "name": "氯沙坦钾片",
      "dosage_text": "每日一次，每次 50mg", "dose_qty": 1, "dose_unit": "片", "dose_times_per_day": 1,
      "dose_slots": ["morning"], "start_date": "2026-08-15" }
  ]
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| effective_date | date | 是 | 变化节点在时间轴上的日期 |
| linked_event_id | uuid | 否 | 关联**已存在**的复查事件 id |
| reason_note | string ≤500 | 否 | 事由自由文本，落库为 med_changes.note |
| stop | array | 否 | `match` 支持 `{"id": uuid}` 或 `{"name": 精确匹配当前进行中条目}`，不唯一→拒绝；end_date 缺省=effective_date |
| start | array | 否 | category 缺省 `long_term`；`temporary` 建议同时给 end_date；`med_kind` 可选 `western`/`tcm`，缺省 `western`；西药结构化用量由 `dose_qty`（正数）、`dose_unit` 与 `dose_times_per_day`（1–4）共同组成，任一存在时必须完整，且次数必须等于 `dose_slots` 数量；`dose_slots` 可选（`["morning","noon","evening","bedtime"]` 子集）；`supersedes` 可指向 stop 中条目形成改量链。旧载荷仅有 `dosage_text` 时仍兼容，但不能直接用于药盒余量计算。整批落库为一条 med_changes + 若干条目变更 |

改量表达：同一变更内 stop + start 且 start 带 `"supersedes": "<被停条目id或name>"`。

## 6. 服务端响应与校验

### 6.1 成功（含 dry_run）
```json
{ "ok": true, "import_id": "...", "created": { "event_ids": ["..."], "report_count": 3, "indicator_count": 24 }, "warnings": [ ] }
```

### 6.2 警告（非阻断）
数据合法但可疑时入库并返回：`{"path": "payload.items[0]", "code": "BP_SYS_LTE_DIA", "message": "收缩压不大于舒张压，请核对"}`。警告入库后可在 App 内标记该条记录（仅"录入质量提示"，非医学提示）。

### 6.3 拒绝（阻断）
HTTP 422：
```json
{ "ok": false, "errors": [ { "path": "payload.event.reports[0].indicators[3].value", "code": "REQUIRED", "message": "value 必填" } ] }
```
常见 code：`SCHEMA`（结构非法）、`REQUIRED`、`ENUM`、`DATE_FUTURE`、`PROFILE_AMBIGUOUS`、`PROFILE_NOT_FOUND`、`MATCH_AMBIGUOUS`、`ATTACHMENT_NOT_FOUND`、`DUPLICATE_IMPORT_ID_FORMAT`（同 id 不同体→拒绝）、`LIMIT_EXCEEDED`。

### 6.4 限制（v1）
单请求 ≤512KB；reports ≤30/event；indicators ≤200/report；measurements ≤500/批；日提交频率 ≤120 次/token（防呆不防攻击，鉴权与 TLS 见技术选型文档）。

## 8. 给"外部 AI 整理"环节的提示词约定（建议）

随 App 提供一段可复制的提示词模板，约束外部模型：① 严格输出本格式 JSON、不要多余文字；② 指标名/单位/参考区间按报告原文照抄；③ 无法确认的字段留空而非猜测；④ 隐去报告上的姓名、身份证号等敏感信息后再处理。**人工核对环节不可省略**——模板最后一行固定提示核对清单（数值位数、单位、阴阳性、日期）。
